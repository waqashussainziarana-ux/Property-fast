# Property Fast

An original, responsive informational website for Property Fast. The service catalogue was used as a subject-matter reference; the identity, layout, images and wording were created for this project.

## What is included

- 18 static pages plus a custom 404 page.
- Home, 11 detailed service pages, service directory, landlord packages, about, contact, contractor enquiries and privacy/website information.
- Generated Property Fast logo and architectural imagery stored locally.
- Responsive CSS, keyboard-accessible navigation, native FAQ accordions, service filtering, reduced-motion support and page metadata.

## Run locally

Requires Node.js 20+.

```sh
npm ci
npm run build
npm run dev
```

Open http://localhost:4173. Stop the preview before running `npm run check`, which starts its own temporary test server. Run `node scripts/test-contact.mjs` for the isolated SMTP-handler tests (no real email is sent).
The HTML is generated by `scripts/build.mjs`; edit content in `src/` and styling/interactions in `public/assets/`. Rebuild to view edits.

## Deploy to Vercel

1. Sign into the intended Vercel account using `vercel login`.
2. From this directory, create/link a NEW project named `property-fast` with `vercel link`. Do not link to an unrelated existing project.
3. Build command: `npm run build`; output: `dist`; framework: Other.
4. Deploy with `vercel deploy` for review; use `vercel deploy --prod` when approved.
5. Verify all routes, mobile/desktop layouts and forms on the actual Vercel URL.

For Git-based deployment, import this repository into a new Vercel project named `property-fast`. The included vercel.json supplies the build settings. SMTP delivery requires the environment variables below.

## Activate SMTP

Any SMTP provider that supports authenticated TLS can be used, including an appropriate free-tier service. An account and an authorised sender must be set up by the owner. No provider account has been created or charged.

Configure the names in `.env.example` as server-side Vercel environment variables. Never put credentials in `public/`, client JavaScript, the repository or chat.

- `SMTP_HOST`, `SMTP_PORT` (usually 587 for STARTTLS or 465 for implicit TLS)
- `SMTP_USER`, `SMTP_PASS`
- `SMTP_FROM`: sender email authorised by the provider. Do not use a visitor email as From.
- `FORM_SECRET`: a long, randomly generated secret used to sign short-lived form tokens.
- `SITE_URL`: exact final HTTPS origin with no trailing slash. Used for canonical metadata and allowed form origin.

Delivery is always addressed to the business email in `src/config.mjs`; a visitor can only set Reply-To, not the recipient. The handler validates inputs, origin, signed time-limited form token, a honeypot and supplementary per-instance request limits. It uses TLS and does not log enquiry contents or credentials.

Before enabling the form on a public production domain, configure a Vercel Firewall rate limit for POST `/api/contact` (and the trailing-slash variant) because in-memory limits do not cover multiple serverless instances. Alternatively add a shared durable limiter. Consider an owner-configured anti-bot challenge if abuse occurs.

No real SMTP delivery has been tested because credentials were not supplied. SMTP acceptance is not proof of inbox delivery. Test with a real enquiry after setup, check the recipient inbox and provider logs, and verify error states. Do not expose secrets in test outputs.

## Launch checks

- Review service availability and the company’s actual scope, qualifications, legal entity and service area.
- No invented customer reviews, accreditation badges, price promises, office addresses or performance statistics were added.
- Replace/review the general privacy information against actual business practices and provider arrangements before public launch.
- The site defaults to `noindex,nofollow` with robots disallow during client review. Set `SITE_URL` and `PUBLISH_INDEXABLE=true`, rebuild and deploy when the owner approves launch. A sitemap is generated when SITE_URL is set.
- No third-party analytics or marketing cookies are installed.
- Review at desktop/mobile widths, check navigation and FAQs, confirm all contact links and test the form end to end.
